# ResumeFlow 首版产品需求

- 基线：全新产品；仓库已有 React、TypeScript、Vite 和 Hono 工作区骨架。
- 依赖：无。

## 背景与目标

提供一个可通过 `docker run` 在本机使用的开源简历编辑器。人可以在网页编辑 Markdown，AI Agent 可以通过 MCP 使用同一组简历能力；两者读取同一份持久化数据，并能看到对方已提交的修改。右侧以 HTML 显示多页纸张预览，服务端导出对应的 PDF。

## 范围与非目标

- 首版只面向本机单用户，不包含账号、多用户协作或公网部署。
- 首版不包含 GitHub Pages 发布、主题切换、插件、历史版本、智能纠错、其他导出格式。
- 截图中出现的个人资料只是视觉参考，不作为产品内置示例数据。

## 已确认需求与决策

### 交付与架构

- 使用 monorepo 组织现有 React、TypeScript、Vite 前端与 Hono 后端，前端 UI 使用 shadcn/ui。
- 首版以单用户本机 Docker 容器交付；简历数据保存在 SQLite，并通过 Docker 数据卷持久化。容器重建后保留数据。
- 开发环境直接启动 Vite Web 与 Hono Server 的 dev 服务，分别支持源码热重载；不使用 Docker 开发热重载。生产镜像由 Hono 提供已构建的前端 dist。
- GitHub Actions 在 PR 上运行检查与容器冒烟测试；`main` 与版本标签通过验证后，将 `linux/amd64`、`linux/arm64` 镜像发布为 `boses/resumeflow`。发布任务从仓库的 `production` Environment Secret 读取 Docker Hub 凭据。
- Hono 提供网页所需的数据接口、SSE 变更通知和 MCP 入口。网页与 MCP 调用同一套读写逻辑，以已提交的数据为准。
- MCP 使用 Streamable HTTP，通过本机地址连接；Agent 对已提交数据的后续查询返回最新状态。MCP 修改名称或正文后，已打开的网页编辑器和分页预览自动更新。

### 页面与交互

- 只提供创建简历入口和简历详情两个页面。入口允许创建简历并进入已有简历；详情页可以返回入口。
- 详情页采用左右布局：左侧 Markdown 源码编辑器，右侧实时 HTML 分页预览。
- 顶部允许直接修改简历名称并导出 PDF。Markdown 与名称的修改自动保存。
- Markdown 渲染规则、纸张 CSS 和分页器由网页预览与服务端 PDF 共用。网页输入后异步重排页面，不为每次按键生成 PDF；服务端导出时运行相同的分页脚本，再从当前已保存版本生成 PDF。
- 首版 PDF 页数和主要分页位置应与网页预览基本一致；不同浏览器的字体度量可能产生少量差异，最终文件以服务端 PDF 为准。
- 参考图仅用于双栏结构、纸张预览与简历排版方向；参考图中的主题、插件、历史、智能纠错等控件不进入首版。

### Markdown 排版语法

- 正文以普通 Markdown 编写，额外使用 `:::left`、`:::center`、`:::right` 表达块对齐，使用 `::::row` 包含两个或三个 `:::cell` 表达左右或左中右分布。容器内仍可使用普通 Markdown。
- 使用 `remark-directive` 解析指令，并只映射产品定义的排版指令；不把代码围栏解释为布局，也不执行 MDX/JSX 或用户输入的脚本。
- 嵌套布局使用更长的外层冒号围栏；`row` 中的单元格按顺序对应左、右或左、中、右。
- 网页预览与 PDF 使用同一份 Markdown 解析、样式和分页规则。无效或不支持的指令给出可定位的编辑反馈，不能静默丢失正文。

### MCP 与网页能力一致

- 网页和 MCP 均可创建、列出、读取、复制、删除简历，修改名称与 Markdown 正文，并导出当前简历的 PDF。
- 两种入口的写入都经过同样的校验与持久化流程；并发编辑不得静默覆盖较新的已提交内容。
- 提交成功后通知已打开的详情页重新读取最新数据；刷新页面和 MCP 再次查询得到相同的名称与正文。

## 验收标准

1. 用户通过 `docker run` 启动单个容器并挂载数据卷后，可在浏览器创建简历、编辑名称与 Markdown、预览多页 HTML 并下载 PDF；重建容器后数据仍在。
2. 左侧 Markdown 的标准语法及指定对齐、二栏、三栏指令在右侧 HTML 预览中正确呈现；导出 PDF 与网页预览使用同一份渲染样式与分页器，多页内容的页数和主要分页位置基本一致。
3. 网页修改并保存后，MCP 读取立即得到最新内容；MCP 修改后，已打开的详情页无需手动刷新即可显示最新内容和对应预览。
4. 网页和 MCP 都能完成创建、列出、读取、复制、删除、修改名称、修改正文和 PDF 导出；过期写入不会静默覆盖较新的版本。
5. 预览与导出不执行简历 Markdown 中的脚本或任意组件代码；本机服务默认仅对本机开放。

## 文档与兼容性影响

- GitHub Pages 发布与远程多人访问若后续需要，应基于本需求的简历数据、渲染和导出能力另行定义；不影响首版验收。

# 当前产品决策

## 版本与发布

- 当前决策：根 package.json 是统一版本入口，Google Release Please 在一个版本 PR 中同步根包和三个工作区子包；子包不独立升级或发布，Web、MCP 与 OpenAPI 版本保持一致。
- 当前决策：业务 PR 运行 CI 和容器冒烟测试；合并至 main 并验证通过后维护版本 PR。版本 PR 审批、合并并通过验证后创建 GitHub Release 和标签，再发布 Docker 镜像；仅审批不触发发布。
- 当前决策：镜像发布使用同一次工作流的 Release Please 输出和对应标签，不依赖机器人标签再次触发工作流。默认工作流令牌权限保持只读，发布任务单独申请写权限；仓库允许 Actions 创建和批准 PR，但工作流不自动批准或合并 PR。
- 为什么：统一版本维护入口，同时保留版本变更的人工审核与发布前检查。
- 边界：Docker Hub 凭据由仓库或 production Environment 的 DOCKERHUB_TOKEN 提供；首次线上发布仍需验证完整链路。
- 权威入口：[版本与发布](./releasing.md)。

## 接口文档与服务端日志

- 当前决策：Hono 提供 Swagger UI 和 OpenAPI JSON，覆盖 REST、历史版本、PDF 与 SSE；输入文档复用 REST/MCP 的 Zod 规则。
- 当前决策：开发日志使用彩色结构化输出，生产日志使用含 UTC 时间的 JSON；请求日志通过请求 ID 关联方法、路径、状态码与耗时，内部错误保留堆栈。
- 为什么：接口参数可直接查阅和调试，服务端问题可通过统一上下文定位。
- 边界：不改变现有业务响应与 MCP 协议；请求日志不采集正文、查询参数、Cookie 或认证头。Swagger UI 静态资源默认依赖 CDN。
- 权威入口：[接口与日志说明](../README.md#接口)。

## Docker 与 Agent 接入

- 当前决策：正式交付采用 docker run；用户自行选择宿主机端口，Web、API、MCP 和 PDF 下载共用该映射端口，数据保存在独立数据卷。
- 当前决策：PDF 使用 Chromium headless shell；镜像在同一依赖安装层移除 Xvfb 及不再使用的依赖，保留全部应用字体和系统后备字体。容器冒烟测试覆盖六种字体和多页 PDF 导出。
- 当前决策：REST 与 MCP 共用数据操作、输入校验、版本冲突处理和 PDF 来源选择。工具发现包含字段说明，明确语言集合整体替换及冲突后的核对流程。
- 当前决策：MCP 下载地址默认沿用请求的外部地址和端口，可通过显式配置指定代理后的基础地址。
- 为什么：人工操作与 Agent 操作遵循相同规则，改变宿主机端口无需同步修改容器内部设置。
- 边界：仍面向本机单用户使用；不自动信任转发头。
- 权威入口：[Docker 使用说明](../README.md#docker-运行)、[Agent 操作说明](../README.md#agent-操作说明)。

## 编辑器与数据一致性

- 当前决策：面向 PC 和笔记本的本机单用户简历编辑器。网页与 MCP 共用简历、语言版本、样式和 PDF 导出能力，写入使用 revision 检查。
- 当前决策：保存请求期间的新输入、语言切换和删除其他语言操作保留最新草稿；语言代码不能重复，删除语言须确认。顶层标题与正文对应当前语言，副本的当前语言标题包含副本后缀。
- 为什么：人工编辑与 Agent 修改应共享一致的数据，并避免异步响应覆盖尚未提交的输入。
- 边界：不包含账号或远程多人协作。
- 权威入口：[README](../README.md)。

## Markdown 与排版

- 当前决策：支持普通 Markdown、既有排版指令及经过白名单清洗的安全 HTML（含 img）；危险标签、事件属性和内联 style 会被移除，样式通过自定义 CSS 设置。标题与正文默认左对齐；`:::center`、`:::left`、`:::right` 指定内容块的对齐方式，标题也继承所在内容块的对齐。
- 当前决策：相邻 left、center、right 自动同行，按左、中、右位置排列，书写顺序不影响位置；缺少的位置留空。单独的位置指令按整块对齐。普通正文、标题、分隔线、重复位置或切换分组类型结束当前行，源码空行不结束分组。
- 当前决策：相邻 `:::cell` 自动分栏，首项左对齐、末项右对齐，其余项居中，支持四项及更多；单项按左对齐块显示，单元格平分可用宽度，长内容在各自栏内换行。显式 `::::row` 用于主动指定行边界，直接包含至少一个 cell。冒号与指令名之间不能有空格。
- 当前决策：左侧正文编辑区顶部的“插入语法”菜单提供左对齐、居中、右对齐和单元格；CSS 模式隐藏入口。插入保留已有正文、补充分隔换行并选中占位文字；光标在已有排版容器内时，新块接在该容器之后，连续插入可组合同行内容，沿用实时保存。
- 当前决策：单换行遵循 Markdown 规则；需要换行时使用行尾两个空格或反斜杠，不添加隐式换行。
- 当前决策：Markdown 和 HTML 图片共用完整 HTTP(S) URL 校验与 PDF 图片获取限制。默认头像仅作用于顶部 h1 后、首个 h2–h6 前的图片，HTML 标题遵循相同边界；进入模块后不因再次出现 h1 或手写头像 class 而恢复裁剪，普通图片保持比例。
- 当前决策：网页预览与服务端 PDF 共用 Markdown 解析和纸张样式。纸张 iframe 内不显示滚动条，多页内容在外层预览区域滚动查看。
- 当前决策：默认纸张采用现代简约排版：h1 为 20pt、h2 为 11.5pt，正文为 10pt、1.5 倍行高，段落上下间距为 1mm；姓名、章节与项目小标题保持清晰层级。
- 当前决策：二级标题文字使用主题色，底部分隔线使用主题色的 22%，宽度为 1px（PDF 约 0.75pt），降低横线的视觉重量；自定义 CSS 可覆盖默认样式。
- 当前决策：编辑器和模板使用常驻 HTML iframe，测量连续内容后按断点裁切为 A4 页面；输入按帧更新，不设置固定防抖。普通块、标题与后文、图片、表格行和短双栏优先完整保留，长文本按实际行边界分页。颜色变化只更新样式，容器宽度变化只调整缩放。
- 当前决策：首页和模板页数共用预览分页算法；只计数时不创建分页展示，计数完成后释放测量 iframe，内容或排版参数变化后重新计数。
- 当前决策：Web、REST 与 MCP 共用 CSS 语法校验；无效 CSS 拒绝保存并提示错误位置，整次请求不得写入任何字段。服务端不自动重写有效 CSS 原文。
- 为什么：排版意图由源码明确表达，预览、导出及 Agent 编辑遵循相同契约。
- 边界：不执行 Markdown 或样式输入中的脚本；用户自定义 CSS 可覆盖默认纸张样式。
- 权威入口：[排版与图片规则](../skills/resumeflow/references/markdown-layout.md)。

## 简历字体

- 当前决策：界面使用 Inter 与明确的系统中英文字体回退，Markdown 和 CSS 编辑区统一采用系统等宽字体栈；界面字体与简历预览、PDF 的独立字体配置分离。
- 当前决策：详情页 header 可为当前语言独立选择思源黑体、阿里普惠体、MiSans、HarmonyOS Sans、Inter 或苹方。zh 及中文区域代码默认思源黑体，其他语言默认 Inter；旧数据未指定字体时沿用对应默认值。
- 当前决策：中文方案优先使用字体自身的中西文字形，Inter 使用固定的思源黑体作为中文后备。字体随语言数据、复制、历史快照与恢复保留；REST/MCP 使用相同的字体 ID 校验并支持按目标语言更新。
- 当前决策：字体以本地资源随应用打包，使用固定版本和内容指纹文件名，不依赖字体 CDN 或用户系统的同名字体。预览和导出在所需字体加载成功后分页，加载失败明确报错。
- 为什么：语言版本可以分别排版，人工编辑与 Agent 操作获得一致的保存和导出行为，Docker 断网时仍可使用内置字体。
- 边界：不做动态字体裁剪；保留自定义 CSS 覆盖默认字体的能力，字体分别遵循各自许可。
- 权威入口：[字体使用说明](../README.md#简历字体)、[字体资源与许可](../apps/web/public/fonts/README.md)。

## PDF 导出

- 当前决策：首页简历卡片的三点菜单提供“导出 PDF”，直接下载卡片当前语言的已保存草稿，无需进入详情页；生成期间显示加载状态并阻止重复点击，失败提示错误并允许重试。
- 当前决策：导出使用已保存版本及指定语言的标题、正文和字体，指定不存在的语言时返回错误；zh 文件名为“标题.pdf”，其他语言为“标题_语言代码.pdf”。网页与 API/MCP 下载采用相同规则，并共用服务端 Chromium 导出流程。
- 当前决策：Skill 下载时保留服务端提供的文件名；无法读取时使用相同的标题与语言规则，历史快照使用快照中的标题。用户明确指定名称时按用户要求命名。
- 为什么：默认中文文件保持简洁，多语言文件可以区分。
- 边界：同应用版本、相同内容、语言和资源的 Web/MCP PDF 内容与排版一致；独立生成文件的时间等元数据不保证相同。网页轻量预览与服务端 Paged.js 的分页算法独立；预览和卡片页数供编辑参考，复杂 CSS、超大元素或字体度量差异可能导致不同分页，最终以服务端 PDF 为准。不包含浏览器原生打印。
- 权威入口：[README](../README.md)。

## 历史版本与实时保存

- 当前决策：实时保存持续更新当前草稿，不为每次自动保存创建历史节点。用户点击 header 的“保存”或按 Cmd/Ctrl+S 时创建不可变快照并自动命名为“版本 N”；内容未变时不重复创建。列表显示标题和创建时间。
- 当前决策：当前内容相对本次打开或上次手动保存仍有修改时，关闭、刷新页面及站内离开编辑页需确认；自动暂存不解除提醒，未修改、改回原内容或手动保存成功后不提示。取消离开保留编辑内容。
- 当前决策：查看历史版本不改动当前草稿；切换前存在未发布修改时，提示取消、放弃修改并切换或保存并切换。首次修改历史内容时，先自动保留当前草稿为“恢复前的草稿”，再以历史快照开始新草稿；原快照保持不变。查看时导出快照，开始编辑后导出当前草稿。
- 当前决策：创建快照失败时提示错误，保留未发布状态并允许重试；失败时不得继续“保存并切换”。发布完成后，期间新增的编辑仍保持未发布状态。
- 当前决策：快照包含所有语言、各语言字体、简历标题、正文和样式；网页与 MCP 均可列出、读取、创建、恢复并导出历史版本。
- 为什么：将日常自动保存与可回看的重要时间点分开，恢复历史时保留未手动创建版本的工作。
- 边界：保留草稿与恢复快照必须原子完成，过期 revision 不得触发归档或覆盖；不提供版本删除、差异对比、合并或多个独立草稿分支。
- 权威入口：[历史版本使用说明](../README.md#历史版本)。
